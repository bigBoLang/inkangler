# inkangler · 墨迹大侠自动钓鱼

> 当前版本 **v1.1.1** —— 版本号只在 `mjd/version.py` 里改一处，标题栏、闪屏、exe 文件属性会跟着变。

> **作者：大波浪**　·　仅供个人自用，**禁止传播、转售或用于任何违法用途**。
> 本程序只做图像识别 + 模拟点击，不修改游戏文件、不注入进程、不上传游戏数据。

给微信小程序《墨迹大侠》的钓鱼小游戏做的全自动脚本：**抛竿 → 遛鱼 → 结算（直接卖 / 留鱼）→ 攒够自动卖鱼**，
全程纯图像识别 + 模拟点击，**不抢鼠标、不抢焦点**（一直用 `PostMessage`，你可以照常用电脑）。

## 图形界面（推荐）

```bash
python tools/fishui.py
```

界面里能直接改：模式、长度阈值、抛竿力度（1~10 档）、钓多少竿、要不要自动卖鱼箱。
设置会自动存到 `shots/ui_settings.json`，下次打开还在。点「开始」前先把游戏停在钓鱼界面。

### 按颜色卖（可多选）

结算弹窗里**鱼名和背后光晕的颜色**就是这条鱼的颜色：**红、黄、紫、蓝、绿、灰**。
在界面「颜色」框里勾上想卖的颜色（可多选），钓到这些颜色就直接点「原价出售」，
**不看长度**；没勾的颜色仍按长度阈值判断。鱼币模式本来就全卖，颜色不影响。

颜色取的是鱼名那一行（y 268~300、x 210~345）的填充色，36 张历史弹窗全部识别正确。
日志里会写 `颜色 紫(H133 S91)`；弹窗还没画全时写 `颜色 ?`，并退回长度规则，不会乱卖。

### 桌面 exe（日常用这个）

桌面上的 **`墨迹大侠自动钓鱼.exe`** 就是上面这个界面，双击即用，不用装 Python、不用开命令行。
exe 的配置、截图、新对话框都存在它旁边的 `墨迹大侠_数据/` 里，不会往桌面散文件。

> **系统要求：64 位 Windows 10 / 11。**
> Windows 7 跑不了 —— Python 3.9 起就不再支持 Win7，启动会直接报
> `无法启动此程序，因为计算机中丢失 api-ms-win-core-path-l1-1-0.dll`
> （这个 DLL 是 Win8 才有的系统 API，装运行库也补不回来）。
> Win10/11 报同样的错，说明系统被精简过，跑 `sfc /scannow` 修复即可。

改完代码重新打包（打包脚本会自动覆盖桌面上的 exe）：

```bash
python tools/build_exe.py             # 正式版：带管理员清单，双击弹一次 UAC
python tools/build_exe.py --no-admin  # 测试版：不提权，只验证能不能启动
```

### 一定要有管理员权限

微信（真正跑小游戏的是 `WeChatAppEx.exe`）如果是**以管理员身份运行的**，普通权限的脚本会被
Windows 的 UIPI 挡在两堵墙外面：

| 症状 | 实质 |
| --- | --- |
| `PrintWindow` 返回 0、截图全黑（只能退回屏幕截图） | 低完整性级别不能读高完整性窗口 |
| 界面一切正常，点「开始」后游戏里毫无反应 | `PostMessage(WM_MOUSEMOVE / LBUTTONDOWN)` 返回 0，输入被过滤 |
| `OpenProcess(pid, VM_READ)` 拒绝访问 | 同上 |

程序开跑前会先探一下（`win.input_blocked()`，用 `WM_MOUSEMOVE` 当探针），被挡就把原因写进
日志和状态栏，不会闷头空跑。界面上的「管理员重启」按钮会弹 UAC 提权重开。

> 反过来没问题：机器人是管理员、微信不是，照样能操作。
>
> 换号 / 重开微信后权限可能变，这是「昨天还好好的、今天点了没反应」最常见的原因。

### 授权（防止 exe 被拷走后到处跑）

程序启动时会先验授权：**没授权就只弹一个激活窗**，上面显示本机机器码，粘进授权文本才能进主界面。

| | |
| --- | --- |
| 机器码 | 注册表 `MachineGuid` + C 盘卷序列号的 SHA-256，形如 `3LVH-Y4NM-SYI7-2J6S` |
| 授权文件 | exe 旁边的 `license.key`（源码版在项目根目录），一行 `MOJI1.…` 文本 |
| 签名算法 | Ed25519。**exe 里只有公钥**，私钥在 `tools/_license/private.pem`，签不出新授权 |
| 绑定 | 机器码不符 / 文本被改过 / 过期 → 一律拒绝，并说明原因 |
| 署名 | 授权里带使用人名字，泄漏出去能查到是谁那份 |

签发（**只在你自己的机器上做**）：

```bash
python tools/lickey.py machine                     # 本机机器码
python tools/lickey.py issue 3LVH-Y4NM-SYI7-2J6S --owner 张三            # 永久
python tools/lickey.py issue 3LVH-Y4NM-SYI7-2J6S --owner 张三 --days 30  # 试用 30 天
python tools/lickey.py status                      # 本机授权状态
python tools/lickey.py verify 别人的license.key     # 校验一份授权
```

给别人开通的流程：他打开程序 → 弹窗上有他的机器码 → 发给你 → 你 `issue` 出
一行 `MOJI1.…` 发回去 → 他粘进激活窗即可。**exe 和 license.key 都发过去也行，
但换台电脑照样跑不起来**（机器码对不上）。

> ⚠️ **`tools/_license/private.pem` 是私钥**，能签出无限多授权：别外传、别放网盘，
> 复制一份到 U 盘/密码管理器备份。丢了只能重新 `init`，之前发出去的授权全部作废、
> exe 也得重新打包（公钥变了）。
>
> **能挡什么**：拷了 exe 就用、发给朋友、传到群里 —— 全部失效。
> **挡不住什么**：把 exe 解包、改字节码绕过校验。那得上服务器校验或加壳
> （pyarmor / VMProtect），成本另算。要更硬的话再说。

### 在线激活（一码一机）

不想手签授权的话，用**激活码**：你发一串 `XXXX-XXXX-XXXX`，对方在激活窗里一贴就自动开通。

| | |
| --- | --- |
| 服务地址 | `https://blog.dabolang.dpdns.org/api/` |
| 跑在哪 | 博客仓库的 Pages Functions：`functions/api/[[path]].js` |
| 存储 | Cloudflare KV 命名空间 `moji-license`（绑定名 `LIC`） |
| 密钥 | `LICENSE_KEY`（Ed25519 私钥，PKCS#8 base64）、`ADMIN_KEY`（管理口令），都是 Pages 环境变量 |
| 规则 | **一码一机**：第一次激活就绑死机器码；同机重复激活允许（重装不折腾）；换机器 → 拒绝；有码可吊销 |

> ⚠️ **激活时先关代理**：开着 v2rayN 这类代理（特别是 TUN 模式）时，激活请求会走代理线路，
> 常见现象是卡十几秒后报 `The handshake operation timed out`。关掉代理直连再点一次就好。
> 程序本身会依次尝试「主域名 → 备用域名 `myblog.dabolang.dpdns.org` → 强制 TLS 1.2」共 4 次，
> 关掉代理后通常一次就过。

日常用法：

```bash
python tools/lickey.py codes --owner 张三 --count 3      # 生成 3 枚码
python tools/lickey.py machines                          # 看谁激活了
python tools/lickey.py revoke 3LVH-Y4NM-SYI7-2J6S        # 吊销某台
curl https://blog.dabolang.dpdns.org/api/health          # {"ok":true,"kv":true,...}
```

### 网页后台（手机也能用）

浏览器打开 **`https://blog.dabolang.dpdns.org/api/admin`**，输一次管理口令（`server/admin.key` 里那串）就能：

- 生成激活码（使用人 / 数量 / 有效期，出码一键复制）
- 查看已激活机器（机器码、使用人、激活时间、到期）
- 吊销机器

口令只存在当前标签页，关掉就没了；同一 IP 连续输错 10 次锁 10 分钟。
不想开浏览器时，双击 `授权管理.bat` 走本地菜单，功能一样。


客户端流程：激活窗里填机器码（自动带出）+ 激活码 → 点「在线激活」→ 服务器签发授权 →
**本地再用内置公钥验签一遍**（不盲信服务器）→ 写入 exe 旁边的 `license.key`，之后离线可用。

> 私钥只在服务器环境变量和本机 `tools/_license/private.pem` 里，**exe 内只有公钥**。
> 管理口令在本机 `server/admin.key`，KV id 在 `server/kv.id`，两个都别外传。
>
> 注意：服务器在 Cloudflare 后面，客户端请求必须带 `User-Agent`，
> 用默认的 `Python-urllib/x.y` 会被挡成 `403 error code: 1010`。

### 两种模式

| 模式 | 结算窗里怎么做 | 默认抛竿 | 鱼箱 |
| --- | --- | --- | --- |
| **喂鱼** | 读到长度 **> 阈值**（默认 **65cm**）就点「原价出售」；比它短的关掉弹窗、留进鱼箱 | 3 档（30%） | 不自动卖（不然留下的小鱼又被卖了） |
| **鱼币** | 不看长度，**一律直接卖** | 10 档（100%） | 攒够 N 条整批卖（默认 12） |

「直接卖掉」不是另找一个按钮：结算窗里那个青绿色按钮（`原价出售`）就是。
新纪录时会多一个橙色的「前往鱼塘」，**只点左边青绿那个**。

### 抛竿力度

抛竿时按住转盘中心，转盘上方会出现一条大圆弧蓄力条（蓝→金）。实测：

| | |
| --- | --- |
| 开始出现金色 | ≈0.3 s |
| 涨满 | **≈1.7 s** |
| 涨满后 | 保持到 ≈3.1 s，再按久反而回落（泄力） |

所以「满力」= 1.7 s，界面上的 10 档 = 满力的 10%~100%（3 档 = 0.51 s）。
满力时长也能改（默认 1.7 s），换了渔场/版本手感不一样时可以微调。

> **踩过的坑**：松手之后那条蓄力弧还会亮大约 0.3 s。轨道识别会把它的**蓝弧当成轨道**、
> 把**金色部分当成进度**（3 档时正好 34%，10 档时能到 100%），于是机器人以为小游戏
> 已经开始了，空打两三帧就判「鱼跑了」——而真正的鱼还要 2 s 才咬钩。表现就是
> 「刚抛完竿反应慢一两秒、还白烧一竿」。现在抛竿后会静默 0.5 s，并且要求连续两帧
> 都识别到轨道才接管。

## 实测

在 `紫霞渔场` 跑了两轮：

| 轮次 | 钓上来 | 鱼跑了 | 轨道消失 | 没进小游戏 |
| --- | --- | --- | --- | --- |
| 40 竿 | 35 | 1 | 3 | 1 |
| 30 竿 | 28 | 1 | 1 | 0 |

单竿遛鱼一般 3~15 秒（偶尔碰上满轨道乱窜的鱼会拖到 40 秒以上，脚本会自动重连继续打）。
自动卖鱼都成功，**跟鱼箱计数逐条核对过，条数和金币都对得上，没有虚报**
（30 竿那轮：箱底剩 5 条 + 新钓 28 条 = 卖 25 + 剩 8，前后一致）。

### 真机 A/B：纯比例 vs 前馈+提前量（同一台机器、同一渔场、机器空闲）

各 10 竿，`--sell-every 0`：

| | 纯比例（旧） | 前馈 + 提前量 |
| --- | --- | --- |
| 钓上来 | 10/10 | 10/10 |
| 平均 \|误差\| | 19.8° | **15.2°（−23%）** |
| 平均覆盖深度 | 0.56 | **0.62（+11%）** |
| 平均遛鱼 | 6.1 s | **5.6 s** |
| 最长一竿 | 13.6 s | **9.5 s（−30%）** |
| 循环帧率 | 14.7 fps | 16.2 fps |

两点要说明：

* 机器空闲时**旧版也能 10/10**，所以这次改动不是「从钓不上来到钓上来」，
  而是**误差更小、尾巴更短**——最慢那竿从 13.6s 缩到 9.5s，窄蓝条（半宽 20° 左右）的鱼明显更稳。
* 10 竿样本不大，逐轮 \|误差\| 在 7~40° 之间波动；真正的把握来自上面那张
  离线回放表（7 万多帧、同一批鱼轨迹、只换控制律：14.8° → 9.5°），两边方向一致。

### 最终全流程验证（默认参数 = 前馈 + 提前量）

## 小游戏机制（实测标定）

点住转盘中心约 1.5 秒再松开 = 抛竿；咬钩要等 1~15 秒，之后转盘外圈出现一条弧形轨道。

| 元素 | 位置 | 行为 |
| --- | --- | --- |
| 蓝色「捕获区」 | 外圈 r≈131~152 | 按住 → 以 ≈+100°/s 向右（φ 增大）走；松开 → 以 ≈−140°/s 向左走；两端被轨道截断，中心只能到 φ≈35~145。**宽度按鱼而定，实测 30~105° 都有，中位数 51°** |
| 金色「进度环」 | 内圈 r≈108~122 | 从 φ=0 起被点亮成橙色；鱼被蓝条罩住时增长，越靠中间涨得越快（贴边 +9%/s，正中间 +17%/s），没罩住 −4.6%/s 回落。绕满一圈（实测能量到的上限 ≈94%，最后几度量不到）鱼就上钩，随后弹结算窗 |
| 鱼 | 贴在轨道上 | 自己来回游（深色鱼身 + 亮眼，专门找眼睛）——见下面「鱼的走位规律」 |

**目标**：让蓝条一直罩住鱼，把金环喂满。

## 鱼的走位规律（从 74 竿运行日志里量出来的）

这是整个优化里最有用的一条：**鱼的走位是有规律的，而且跟蓝条怎么动没关系。**

| 量 | 实测 |
| --- | --- |
| 一段直游的时长 | 中位数 **2.9 s**（一半落在 2.3~3.4 s） |
| 一段直游的弧长 | 中位数 **106°**（一半落在 78~142°） |
| 右向速度 | 中位数 **+37.9°/s** |
| 左向速度 | 中位数 **−40.4°/s** |
| 折返位置 | 约 2/3 发生在轨道两端（φ<20 / φ>160），其余在中间随机折返 |

关键推论：

* 鱼的速度基本恒定（左右几乎一样快，≈±40°/s），**只有方向在 3 秒左右翻一次**。
  所以「拿最近的鱼速外推」几乎就是精确预测。
* 折返时蓝条与鱼的距离，中位数是 13°，和全体帧的中位数一模一样
  ——**蓝条凑近并不会把鱼吓跑**，鱼不躲蓝条，蓝条也赶不动鱼。所以只能靠跟得准，不能靠赶。
* 鱼速 40°/s、纯比例控制稳态误差 = v/kp = 10°，再加一帧延迟 40×0.15 ≈ 6°，
  实际滞后 ≈17°。而捕获区半宽常常只有 15~25°，鱼就一直在区边上蹭进蹭出，
  进度涨不起来 —— 这正是「鱼丢了 / 一竿磨几分钟」的根因。

## 控制律

误差 `e = φ_鱼 − φ_蓝条中心`。按住平均 +100°/s、松开 −140°/s，所以「让蓝条停在原地」的
占空比是 140/240 ≈ 58%。先用一个 sigma-delta 累加器把「期望速度」变成逐帧的
「按住 / 松开」，避免蓝条在两个极端之间来回撞。

**纯比例不够用。** 老版本是：

```
v = clip(kp · e, −130, +90)          # kp = 4
```

稳态误差 = v_鱼/kp = 40/4 = 10°，再叠加一帧取图/下发延迟 v_鱼×0.15 ≈ 6°，
实测滞后 ≈17°；而捕获区半宽常常只有 15~25°，鱼就一直在区边蹭进蹭出。

**用鱼的规律做前馈。** 因为鱼是「近似匀速直线 + 到点掉头」，速度估计非常可靠，
于是把估出来的鱼速直接前馈，并按延迟把瞄准点往前推：

```
v_est = 最近 0.35s 鱼位置的斜率           # 掉头时窗口内正负抵消，平滑过零
aim   = φ_鱼 + v_est · T_LEAD             # T_LEAD = 0.15s
v     = clip(v_est + kp · (aim − φ_蓝条中心), −130, +90)
```

前馈把稳态误差从 `v/kp` 抹掉，提前量把延迟补掉，剩下的只有估计噪声。

两处配套的小处理：

* **窗口取 0.35s**（不是更长）：鱼一段直游才 2.9s，窗口越长折返越迟钝。
  离线扫参 0.25/0.35/0.45/0.55/0.75s，|误差| 9.45→9.73°，短的略好、长的略差；
  0.35 是「跟得上折返」和「滤得掉量化噪声」的折中。
* **偶尔一两帧找不到鱼**（被宝箱图标挡住、鱼贴着色块）时，用「上次位置 + v_est 外推」
  顶住（`FishTracker.predict`，最多顶 0.7s），而不是原地不动或者松手。
  鱼的规律是匀速直线，外推 0.3s 内基本就是真位置。

**离线回放验证**（`tools/simctl.py`，把日志里真实的鱼轨迹喂给控制律，
人为加 0.13s 感知延迟，全部运行日志 / 7 万多帧）：

| 控制律 | 平均 \|误差\| | 平均覆盖深度 |
| --- | --- | --- |
| 纯比例（旧） | 14.8° | 0.582 |
| 只加提前量 | 12.1° | 0.672 |
| 提前量 + 鱼速前馈 | **9.5°** | **0.759** |

覆盖深度 0.582 → 0.759 意味着鱼从「贴着区边」变成「基本居中」——
按实测曲线，进度的增速也就从贴边的 ≈+9%/s 提到居中的 ≈+17%/s。
最能说明问题的是模拟里那几竿「鱼跑了」的：|误差| 16.7° → 6.2°，深度 0.27 → 0.76。
（提高 kp 还能再降一点点，4→6 只差 0.14°，但真机上会放大识别噪声，不值当。）

## 帧率 / 机器负载（比调参重要）

这个控制回路对**帧率**极其敏感，因为鱼一直在动：一帧 0.1s 鱼就走 4°，
一帧 1.7s 鱼就走 68°，什么控制律都追不回来。

| 情况 | 帧间隔 | 遛鱼表现 |
| --- | --- | --- |
| 机器空闲 | 0.04~0.05s（20~25 fps） | 正常，老版本也能钓上来 |
| 有点忙 | 0.1~0.15s（7~10 fps） | \|误差\| 从 17° 涨到 28°，鱼开始频繁丢 |
| 机器被占满 | 0.8s 中位，还夹 1.7~2.6s 的整段停顿 | 基本跟不住，一竿磨到超时 |

实测遇到过：后台一个 `tinyMediaManagerCMD` 扫描媒体库，**占了 23 个核**，
遛鱼循环直接从 20 fps 掉到 <1 fps，鱼在相邻两帧之间就跳出去 40°。
这不是控制律的问题——这时候**先关掉别的重负载程序**再跑。

脚本每次结束会打一行 `耗时统计: 帧间隔 中位 … fps | 抓图 … 分析 … 找鱼 …`：

* `fps < 8` 或「最大」超过 1000ms：本机被别的程序拖住了，别怀疑参数。
* 抓图占大头（正常 ~36ms）：是 `PrintWindow` 在等游戏窗口响应；
  分析/找鱼占大头（正常 ~12ms + ~5ms）才是脚本自己慢。

也正因为这个原因，**「鱼位置突然跳一大截」默认不当误检丢掉**（`--jump-guard` 默认关）：
排查下来那些跳变几乎都是游戏掉帧 / 我们卡了一两秒，跳的幅度正是鱼在那段真实时间里游出来的，
丢掉它反而跟丢。留这个开关，是给以后「画面干净、帧率稳定」时再验证用的。

## 角度约定

用 φ（而不是常见的目标角）是为了绕开 ±180° 的环绕：φ = 0 落在轨道**左端**，
+90° 在正上方，右端约 176°。整条轨道按 176° 算，所以「进度 100%」对应 φ≈166。

## 关键实现点

* **截图**：`PrintWindow` + `PW_RENDERFULLCONTENT`（`win.grab_window`）。窗口被挡住也不影响，
  不需要把窗口放到最前面。偶发会出现「重影帧」，但对识别无碍。
  `PrintWindow` 失败时（见下面的「权限」）自动退回**屏幕截图**（`grab_rect`）——
  这种模式下游戏窗口必须真的露在屏幕上、不能被别的窗口盖住。
* **输入**：`PostMessage`（`win.PostInput`）把鼠标消息投给子窗口 `Chrome_RenderWidgetHostHWND`。
  真实光标和焦点都不动。
* **窗口大小无关**：所有截图统一缩放到 `win.CAPTURE_SIZE = (552, 991)`，点击坐标再按真实
  窗口尺寸缩回去（`image_to_screen` / `PostInput.move_to`）。所以窗口拉大拉小，
  ROI 和 `ui.ELEMENTS` 里的坐标都不用重标定（实测 552×991 → 522×981 缩放是线性的）。
* **几何**：轨道圆心/半径是硬编码常量 `arc.REF_GEOM`（基于 552×991 的窗口截图），
  不每帧拟合；要重新标定就用 `arc.analyze(img, fit=True)` 或 `tools/arc_debug.py`。
* **蓝条判定用亮度**：捕获区 V≈245、藏青底 V≈126，差得很开。用色相/饱和度阈值会因为
  捕获区自身的青→淡蓝渐变而只截到一半，蓝条位置就会在两端乱跳。
* **金环判定用色相**：进度环是橙色（H 8~35），按 r=108~122 单独采样，
  每个 φ 格里橙色采样点占比 ≥0.4 才算点亮。**不能**用整圈橙色掩码去数连通段——
  转盘的金色外圈、宝箱图标都会混进来。
* **读文件**：`cv2.imread/imwrite` 在中文路径下会静默失败，统一用
  `np.fromfile + cv2.imdecode` / `cv2.imencode + tofile`。

## 结算窗：读长度 / 找「原价出售」

结算弹窗里那行金色小字 `长度:62.8CM` 是自己认的，没有装任何 OCR 库：

* 取 `y 488~522, x 165~390` 这条带子，按金色掩码（`r>190 & g>130 & b<140 & r-b>55`）
  做列投影切字（列宽 ≥2px 算一个字）；
* 每个字裁出来后放进 26×16 画布，和 `mjd/digit_bank.npz` 里的模板做最近邻
  （模板由 `shots/dialogs/` 里 36 张历史弹窗训练，留一验证 298/298 全对）；
* 认出来的字串直接跑正则 `(\d+(?:\.\d+)?)CM`——行首的「长度:」和行尾多切出来的杂字
  （比如有条鱼的红鳍扫进掩码）都自动忽略。整行是**居中**的，所以不能用固定坐标切数字。
* 文字是淡入的，所以第一帧认不出来时会重读几次（最多 1.5s）。

「原价出售」不靠认字，靠颜色 + 位置：青绿色 `(57,158,123)` 的圆角块，落在
`y 548~636` 这条横带里。新纪录时会多一个橙色的「前往鱼塘」，取**最左边**那个就对了。

两种意外情况：

* **滚动公告盖住按钮**：先按已知坐标盲点一次（`(280,591)`，双按钮时再用 `(189,591)`），
  点完检查画面是否真回到钓鱼主界面（转盘下方那块木头的颜色比值）。不放心就不硬点。
* **新纪录动画**：按钮还没画出来 → 每 0.5s 重找，最多 12s；实在找不到就关掉弹窗
  （这条鱼留在鱼箱里，日志里会写 `!! 一直没找到「原价出售」`）。

## 卖鱼流程

1. 主界面点左下「鱼箱」→ 弹出鱼箱面板（`鱼箱容量 N/50`）。
2. 点「前往售卖」→ 4×12 网格，逐格点一下打勾。
3. 点底部「出售」→ 弹「恭喜获得」金币结算，点面板外的暗区关掉。
4. 列表刷新出还没卖的鱼，重复 2~3 直到网格空了（显示「暂无可售卖的鱼~」）。
5. 关掉售卖面板和鱼箱面板，回到钓鱼界面。

网格坐标：列 x = 123/222/321/420，行 y = 400/512/605（第三行被「出售可获得」横幅压住一半）。
判空格子不能只认灰色——格子底色按鱼的稀有度分红/蓝/紫/灰，所以改成
「中心 60×60 里有多少像素不是面板的米黄底」，占比 >0.65 即认为有鱼。
